# Pizza Sales SQL Analysis

An analysis of a pizza restaurant's sales data using MySQL, covering revenue, product performance, customer ordering patterns, and time-based trends. The project progresses from basic aggregations to advanced analysis using CTEs and window functions.

## Dataset

Source: [Pizza Place Sales dataset on Kaggle](https://www.kaggle.com/datasets/mysarahmadbhat/pizza-place-sales)

The dataset consists of four related tables:

- `pizza_types` – pizza names, categories, and ingredients
- `pizzas` – pizza sizes and prices, linked to pizza_types
- `orders` – order dates and times
- `order_details` – individual pizza items within each order, including quantity

## Tools Used

- MySQL Workbench
- MySQL (with CTEs and window functions)

## Database Schema

```
pizza_types (pizza_type_id, name, category, ingredients)
        |
pizzas (pizza_id, pizza_type_id, size, price)
        |
order_details (order_details_id, order_id, pizza_id, quantity)
        |
orders (order_id, order_date, order_time)
```

`pizza_types` connects to `pizzas` through `pizza_type_id`. `pizzas` connects to `order_details` through `pizza_id`. `order_details` connects to `orders` through `order_id`.

## Key Findings

- Total revenue: $817,860.05 across 21,350 orders and 49,574 pizzas sold.
- The Classic category generates the most revenue overall, but individual Chicken pizzas (Thai Chicken, Barbecue Chicken) are the top earners by pizza.
- Large is the most popular size by a wide margin; XL and XXL sizes make up a very small share of sales.
- Friday is the busiest day and 12–1 PM is the busiest hour; Thursday's lunch hour (12–1 PM) is the single busiest combination.
- Revenue is fairly stable month to month, with July as the strongest month. November saw the largest month-over-month growth, and December the largest decline.
- Pizza demand does not vary much by season, suggesting fairly consistent year-round demand rather than a seasonal product.

## What This Project Demonstrates

- Multi-table joins across a four-table relational schema
- Aggregate functions (SUM, COUNT, AVG) with GROUP BY
- String manipulation (LENGTH, REPLACE) to derive data not directly available in a column
- CASE WHEN logic to bucket data into custom categories
- Common Table Expressions, including chaining multiple CTEs
- Window functions: RANK() with PARTITION BY, SUM() OVER() for running totals, LAG() for period-over-period comparison
